# specs/backfill.md — 离线回填 / 预调度通知（备份恢复见 specs/backup.md）

## 一、离线回填

### 为什么难

关掉 App 几小时后重开，世界应该像继续运转过。但 App 当时并没有在跑——这段历史只能在重开的
瞬间编出来，而两个方向翻车都很难看：

- **编多了**：回来面对 40 条没人信的未读，一眼假；
- **编错时间**：设定成夜猫子的朋友，早上六点给你发消息。

所以 `simulate()` 只负责决定「什么时候本该发生什么」：**不调 LLM、不碰存储、不读挂钟**，
是输入的纯函数。调用方把结果物化成 `fireAt` 在过去的 `scheduled_actions`，交给平时那个执行器
排空——实时与回填因此走同一条代码路径（宪法铁律 5），而不是第二套时间推进逻辑。

### 四条硬规则（都有单测钉住）

1. **窗口** = `(上次前台化屏障, now - 2min]`。屏障每次前台化落盘，绝不向屏障之前插入。
   末尾留 2min 余量，避免与正在播放的实时消息撞车。
2. **活跃时段**：时间戳必须落在人设 `activeHours` 内；交集为空就**沉默**。
   沉默不是退化行为——它本身才是最像真人的结果。
3. **限额**：≤3 人开口、每人 ≤2 条、帖 ≤6、每群每离线小时 ≤6 条、LLM 调用总数 ≤8。
   >24h 只回填最近 24h。
4. **不得倒挂**：每条回填消息必须**晚于该会话的最后一条**。行是「现在」插入的，
   时间戳倒挂会直接破坏 `rowid 序 == 时间序`，而游标分页正依赖这个不变量
   （见 `specs/data-schema.md`）。

### 骨架先行

`runBackfill` 排完队就返回，正文交给常规 drain 生成。未读红点与会话预览立刻可见，不必等网络。
首次启动（无屏障）只落屏障、不编历史——给一个从没打开过的 App 伪造往事是荒唐的。
回填异常被吞掉，绝不阻塞启动。

### 确定性

种子 = `${seed}:${from}:${to}`，同一个离线窗口永远得到同一份计划。重开不重摇。

## 二、预调度通知

无服务器意味着：**能在 App 关闭时弹出的通知，必须在关闭之前就连正文一起排好**。
这一条约束推导出下面全部设计。

### 内容分级（`canPregenerateBody`）

| kind | 可预生成正文？ | 为什么 |
|---|---|---|
| `greeting` 早晚安 | ✅ | 锚定在时刻上，含义不依赖期间发生了什么 |
| `festival` 节日 | ✅ | 锚定在日期上 |
| `promise` 约定提醒 | ✅ | 锚定在约好的时刻上 |
| `followup` 追问 | ❌ | 引用近期对话；到点时对话可能早已走远，预览就是错的 |

`followup` 一律用微信原生的 **`[你收到一条消息]`** 无预览样式。

### 一致性铁律

通知展示过的正文**必须**原文入库、且 `createdAt === fireAt`。用户可能已经在锁屏上读过；
打开 App 却看到不同的文字、或同样的文字挂在不同时间，是最刺眼的一种穿帮。

### 平台

- 原生：`@capacitor/local-notifications`（已装 v7，对齐 Capacitor 7）。
- Web：浏览器无法为「没在运行的页面」排期，故 `scheduleNotifications` 在 Web 上返回 0，
  由返回值如实反映平台实际接受了几条——不谎报成功。无权限时静默 no-op。
- **真机锁屏验证需要 APK**（M5 构建范畴），本轮只保证代码路径就位。

每次回前台 `cancelAll()` 全量撤销重排：还挂着的通知是按用户已经走过的世界状态写的。

## 三、备份 / 恢复（.aiwx）→ 见 `specs/backup.md`

备份自 M-I17（增量 / 货架 / 自动备份）与 M-I18（内容哈希判据 / 删除墓碑 / 设备本地行清单 /
中断可知）之后已自成一块，规格移到 **`specs/backup.md`**，此处只留与回填相关的一条接口：

**恢复完成后必须重置 `lastForegroundAt` 屏障**。恢复来的包可能是几天前的；不重新架屏障，
下一次前台 pass 就会把那整段空档当成「你不在的时候」，用编出来的活动填满它。
`restoreBackup` / `applyIncrementalBackup` 结尾都写这一行，`backup-crypto.test.ts` 钉住。

## M-I5 · 离线社交回填扩展

- **赞评离线可发生**：`SimInput.recentMoments`（离线前已存在的最新几条帖，
  由前台 pass 读入——simulate 保持纯函数）。预算 `LIMITS.socialReactions`（含
  赞与评，赞零 LLM 成本）；作者绝不自赞；反应时间恒晚于帖子时间；48h 以上
  的旧帖不再吸引反应。
- **AI↔AI 私信离线可发生**：每次离线至多 `LIMITS.offlineDms`（=1）场，配对取
  自共同群、种子化；<3h 的短离线不排（私聊需要时间差才可信）。事件**不带**
  群 convId——会话发生在隐藏私信线程，带了会误入群「≤2条/15分钟」限速账本
  （测试逮住过一次）。私信完成后的孵化（八卦外溢/joint_plan/agent_forward）
  经同一个 handler 自动发生。
- 物化 payload 与在线 handler 同形：赞评带 momentId，私信带 {a,b,groupId,fireAt}。
