# spec: 首次体验（三步引导）

**文件**：`src/features/welcome/WelcomePage.tsx`（页面）、`src/features/welcome/welcome.ts`（纯规则 +
问候排期）、`src/App.tsx` 的 `RootRedirect`（首启跳转）、`appStore.freshInstall`（水合时种子写入的信号）。
**基准**：没有微信对照物（微信的首启是登录）。版式用微信的语汇：白底、居中大标题、灰色说明、
底部绿色主按钮、右上角「跳过」。

## 为什么

M-J 末的首启是：种子数据 + 聊天页一条「未配置 API key」横幅，没有引导。新装的人看到的是一个
「别人的微信」——四个朋友、几段聊天记录——却不知道这些人会不会说话、要怎样才会说话。三步把这件事
讲清楚，并且让第三步**真的发生**：第一条问候是她此刻用接上的模型写的，不是预设台词。

## 三步

1. **接上一个模型**：显示当前是否有可用的模型（`hasUsableProvider`）。没有 → 「去接一个」进
   **现有的** `/settings/api`（预设、测试连接、拉模型列表都在那里，引导页不复制第二份表单），
   返回时重新检查；有 → 「✓ 已接上」。这一步可以不接直接下一步。
2. **认识朋友**：种子里的 AI 联系人，头像 + 名字 + 人设的第一句；点选「谁先来打招呼」，默认第一位。
3. **她马上会来找你**：「进入微信」→ 记下已引导 → 回会话列表。接了模型时为选中的朋友排一条**一次性**
   问候；没接时换一句「接上模型之后，他们会自己来找你」，不排问候（没有模型时引擎只能给人设化兜底句，
   第一印象就是一句「信号不太好」）。

步骤在 URL 里（`/welcome?step=2`），所以去设置页接模型再返回不会丢步。右上角「跳过」在每一步都在：
记下已引导、直接进会话列表、不排问候。

## 规则

- **只给全新安装看**：`doHydrate` 发现仓库为空、写入种子时置 `freshInstall`；跳转条件是
  `freshInstall && !onboarded`。已经在用的人（仓库非空）**永远**不会被引导页拦住——这条最要紧，
  用户本人的手机就是一个老安装。「已引导」存 localStorage `ui.onboarded`：与 `ui.theme` 同类，是
  这台设备的显示状态，不进 settings 表、不进备份。
- **问候走铁律 5**：排进 `scheduled_actions`，kind 复用 `heartbeat`，payload 带 `at`（= fireAt）——
  于是它按 `isChainOneOff` 是一次性行，不续链、也不被当成「链已就位」（M-K9 修的分叉病正是这里）。
  id 固定 `welcome_<contactId>`，排之前 `actionExists`（一辈子一次，宪法 2）。fireAt = 进入后约 4 秒：
  人刚回到会话列表，消息落地、未读角标亮起、提示音响——「真的到达」就是这一刻。
- 文字是**生成的**：handler 走 `sendProactiveMessage`（没有预写 body），她用自己的人设开口。

## 只在根路由上拦

跳转做在 `/` 的重定向里（`RootRedirect`：全新安装且未引导 → `/welcome`，否则 → `/chats`），而不是
在 App 里「水合完了就 navigate」。真机每次启动都从 `index.html` 的根进来；深链（通知、小组件）、
测试、手输的 hash 路由都是**指名**进来的，不该被引导页截走——截图与 e2e 的浏览器每次都是全新安装，
要是在任意路由上拦，整套门禁第一屏全成了引导页。

## 验收

- [x] 跳转判据（只有全新安装且未引导）/ 问候是一次性行、只排一次、只在接了模型时排 / 跳过不排问候
  （`tests/unit/k9-welcome.test.ts`）。
- [x] 引导页**懒加载、无 golden**：一台设备一辈子只看一次，放进主包等于让每一次冷启动为它付 2KB
  （实测把主包推到 308.33 / 308）；懒页的首帧是 Suspense 兜底，按 J7 的规矩不许带 golden——三步
  由 jsdom 渲染测试逐步断言。
- [ ] 真机：首装 → 接模型 → 返回 → 选人 → 进入，四秒后问候到达且有提示音；老安装升级后不出现引导。
