## 为什么是「脱胎换骨」而不是「再加功能」

M-A 到 M-J 十轮把功能面铺到了头：单聊、群聊、朋友圈、红包转账、通话、剧情、原生后台、
2,101 条单测、27 份 spec。开轮前我把 60 条路由逐一截图过了一遍，结论很直接——
**功能是满的，皮是原型的皮**：

| 现场 | 真微信 8.0 | 本 App（M-J 末） |
|---|---|---|
| 聊天页「＋」面板 | 白底圆角方块 + 深灰线性图标，两页带分页点 | **纯色方块，没有图标** |
| 表情面板 | 百余个表情 + 最近使用 + 底部 tab + 浮动「发送」 | 24 个 emoji + 一行退格 |
| 拆红包 | 居中红包卡，弧形封口，金色「開」压在弧线上 | 整屏红色 + 左上角 × |
| 红包详情 | 顶部红色弧形头 + 头像 + 大号金额 | 灰底纯文字 |
| 转账 | 自定义数字键盘 + 绿色「转账」键 | 系统输入 + **橙色**按钮 |
| 设置 | 新消息通知 / 聊天 / 通用 / 隐私… 分层子页 | 一张长长的功能清单，夹着解释段落 |
| 个人资料 | 头像/名字/拍一拍/微信号/二维码 逐行进子页 | 一张表单 + 色板 |
| 人设编辑 | — | 浏览器原生 `<select>` 与蓝色 `range` 滑条 |
| 深色模式 | 全套 | **没有**（PLAN 的 V3/M6 项，至今未做） |
| 字体大小 / 聊天背景 | 有 | **没有**（同上，V3/M6 遗留） |
| 首次打开 | — | 种子数据 + 一条「未配置 API key」横幅，没有引导 |

还有看不见的那一半：主包 342KB gz（未压缩 983KB），全部 25 个调度 handler 与它们背后的
AI 子系统都在冷启动里解析；`ChatPage.tsx` 1,842 行。

所以这一轮的北极星是三句话：

1. **装在手机上分不出真假**——每个用户每天会看见的面，按微信 8.0 Android 重做到位；
2. **夜里也好看**——深色模式、字体大小、聊天背景这三项 V3 欠账一次还清；
3. **打开就能用、打开就很快**——首次引导 + 启动瘦身。

## 工作约定（本轮新增）

- **golden 走 CI**：凡改 UI 的推送，tip 提交信息带 `[regen-goldens]`；回推的基线拉回本地后
  **逐张肉眼看一遍**再继续（门禁是自指的——它只保证「和自己上次一样」，不保证「对」）；
  然后在上面再推一个普通提交，让门禁真的复核一次新基线。
- **深色不许靠组件里的条件分支**：一切走 `[data-theme="dark"]` 下的 token 重定义；
  语义 token 每一个都必须在深色下表态（重定义，或登记为「主题无关」并写理由）——
  漏一个就是深色下的一块亮白补丁，而且没有任何检查会说话（同 J13 的未定义变量）。
