## 为什么是「脱胎换骨」而不是「再加功能」

M-A 到 M-J 十轮把功能面铺到了头：单聊、群聊、朋友圈、红包转账、通话、剧情、原生后台、
2,101 条单测、27 份 spec。开轮前我把 60 条路由逐一截图过了一遍，结论很直接——
**功能是满的，皮是原型的皮**：

| 现场 | 真微信 8.0 | 本 App（M-J 末） |
|---|---|---|
| 聊天页「＋」面板 | 白底圆角方块 + 深灰线性图标，两页带分页点 | **纯色方块，没有图标** |
| 表情面板 | 百余个表情 + 最近使用 + 底部 tab + 浮动「发送」 | 24 个 emoji + 一行退格 |
| 拆红包 | 居中红包卡，弧形封口，金色「開」压在弧线上 | 整屏红色 + 左上角 × |
| 红包详情 | 顶部红色弧形头 + 头像 + 大号金额 | 灰底纯文字 |
| 转账 | 自定义数字键盘 + 绿色「转账」键 | 系统输入 + **橙色**按钮 |
| 设置 | 新消息通知 / 聊天 / 通用 / 隐私… 分层子页 | 一张长长的功能清单，夹着解释段落 |
| 个人资料 | 头像/名字/拍一拍/微信号/二维码 逐行进子页 | 一张表单 + 色板 |
| 人设编辑 | — | 浏览器原生 `<select>` 与蓝色 `range` 滑条 |
| 深色模式 | 全套 | **没有**（PLAN 的 V3/M6 项，至今未做） |
| 字体大小 / 聊天背景 | 有 | **没有**（同上，V3/M6 遗留） |
| 首次打开 | — | 种子数据 + 一条「未配置 API key」横幅，没有引导 |

还有看不见的那一半：主包 342KB gz（未压缩 983KB），全部 25 个调度 handler 与它们背后的
AI 子系统都在冷启动里解析；`ChatPage.tsx` 1,842 行。

所以这一轮的北极星是三句话：

1. **装在手机上分不出真假**——每个用户每天会看见的面，按微信 8.0 Android 重做到位；
2. **夜里也好看**——深色模式、字体大小、聊天背景这三项 V3 欠账一次还清；
3. **打开就能用、打开就很快**——首次引导 + 启动瘦身。

## 工作约定（本轮新增）

- **golden 走 CI**：凡改 UI 的推送，tip 提交信息带 `[regen-goldens]`；回推的基线拉回本地后
  **逐张肉眼看一遍**再继续（门禁是自指的——它只保证「和自己上次一样」，不保证「对」）；
  然后在上面再推一个普通提交，让门禁真的复核一次新基线。
- **regen 推送之后、机器人回推之前，不要再推任何提交**（K4 踩过）：regen job 在开跑时
  checkout 分支尖端，中途有新提交，它回推时就是非快进、被拒，基线没铸上；而那个新提交
  自己又不带标记，截图门禁对着旧基线跑、必然红。下一个带标记的提交会把两边一起补上。
- **深色不许靠组件里的条件分支**：一切走 `[data-theme="dark"]` 下的 token 重定义；
  语义 token 每一个都必须在深色下表态（重定义，或登记为「主题无关」并写理由）——
  漏一个就是深色下的一块亮白补丁，而且没有任何检查会说话（同 J13 的未定义变量）。

### 这一轮挖出来的真 bug

「换皮」轮挖出的 bug 比功能轮还多——因为换皮要逐像素看每一屏，而功能轮只看功能通不通：

1. **K0**：聊天页的「＋」被长输入框挤出屏幕；发红包 / 转账的金额输入框整个在屏幕外——旧 golden 一直在保护它。
2. **K2**：消息长按菜单十个动作排成一排，后六个（转发 / 收藏 / 删除…）在屏幕外。
3. **K5**：`Number(null) === 0` 让「没设过字号」读成最小档（上线前抓住）。
4. **K7**：朋友圈封面的 `overflow: hidden` 把挂出下沿的头像切成 64×44 的扁块，两轮；朋友圈字号写死 px，
   「字体大小」管不到它，而那三个字号 token 早就定义着、从没被用过。
5. **K8**：种子把人数写死进群**名**（「周末爬山小分队(5)」）；资料页被联系人列表的白底刷白，分组之间什么都没有。
6. **K9**：自续链被一次性行分叉——每次 nudge、每次长时间离开后的回填，都给同一个人再接出一条心跳 /
   发帖 / 私信链。她越被晾、你离开越久，她的主动消息越多。
7. **K12**：气泡按压的两个 token 从 M1 起定义着、全仓没人用；深色模式下开关圆钮是一颗黑扣子。

### 新守卫（每一条都变异验证过）

THEME_INVARIANT 台账（深色下每个语义 token 必须表态）· 原生 `<select>` / `type="range"` 禁入 ·
冷启动形状（调度运行时 / SQLite / virtuoso / 引擎树都不许回主包，ai/engine 的静态导入方台账）·
封面不许裁切 · 群人数派生 + 种子名订正 · 一次性行不续链 + 分叉剪枝 · 首次引导只拦全新安装的根路由 ·
定义了却没人用的颜色 token 不许存在。

### 教训

1. **门禁是自指的**：golden 只保证「和上次一样」。被切扁的头像、屏幕外的输入框、群名里的人数，都是在
   bug 之后才铸的基线，门禁照单全收。所以每次 regen 回来逐张肉眼看——本轮靠的正是这一步。
2. **「定义了却没人用」和「用了却没定义」一样安静**。J13 守了后者，前者让按压态从 M1 一直缺到现在。
3. **说出去的数字要量过**：K8 的提交信息写了「主 305.6」，实测 306.27；K12 第一版测试整份没跑，而我只
   grep 了「Tests」汇总行，被同一次运行里别的文件的通过数盖住了——是变异验证跑出「no tests」才发现的。
4. **违反宪法第 0 条第 7 款一次**：K6 的提交 `b688138` 带了 `Co-Authored-By: Claude…` 与 `Claude-Session:`
   尾注。没有改写历史（CI 正跑在那条分支上，且改写已推送的历史需要用户点头）——**待用户决定**。之后的
   每个提交都核对过尾注为零。
