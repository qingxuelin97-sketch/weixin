本轮最值得记住的不是新功能，是五个「门禁在说谎」：
- device-test 的原生断言因逐行 shell 语义从来没执行过，而 verdict 只说结果文件不存在；
- notify-record-posted 是假绿——它 grep 整份 dumpsys，而每个已安装应用都有那行；
- 「每个声明的索引都有读者」把声明文件也算进语料，因而不可能失败，藏住了 story_saves.byScript；
- contact-profile 的 golden 把 .contact-card 类名撞车造成的 232px 破版当成基线固化，
  截图门禁于是一直在保护这个 bug；
- regen 回推的那次基线提交，我以为它「走普通截图门禁、正好复核刚铸的基线」——其实
  GitHub 对 GITHUB_TOKEN 的 push 一律不派发工作流，那次回推名下根本没有 run。
前四条都已修复并各自换成「改坏即转红」的守卫；第五条改的是文档与注释，
并在回推提交上面再推一个普通提交，让门禁真的复核了一遍新基线。

另有两个真机上才会发作、离线永远看不见的缺陷：
- moment_post 有两个「排下一条」的主人，id 不同因而 upsert 折叠不掉，配好 Provider 后
  待办与账单按周期翻倍（离线时两次 Date.now() 同毫秒，恰好在所有测试里都正常）；
- 通知频道建在权限闸之后，而 POST_NOTIFICATIONS 在 Android 13+ 默认拒绝——授权之前
  系统设置里根本没有「消息」「来电」两个分类可调。
